## Findings

- **[fragile] tests/test_harness.py:82-93 — `test_the_guard_loads_for_a_run_of_src_alone` checks that *a file named* `<repo>/conftest.py` is registered, not that the guard is active.** That is a proxy for the property, and it stays green when the property is gone. Mutation, run in an index copy: move the guard back to `tests/conftest.py` and leave any root `conftest.py` (I used a one-line docstring). `tests/test_harness.py` gives **11 passed**. A probe test placed under `src/stacs/` and run with `pytest src/stacs/zz_probe_test.py` then **made a real DNS lookup of example.com and passed**. So the regression this test exists to catch, doctests run unguarded via `pytest src/...`, gets through as soon as the root conftest holds anything else. That is likely, because a root conftest attracts other fixtures. The commit message's mutation ("moving the guard back into tests/ turns one test red") only holds when the root file is deleted. It does not hold when the root file is emptied or repurposed.
  Fix: assert the behaviour in the child process, not the file. For example, run the child as `python -c` with `pytest.main([... "src/stacs/verify.py", "--collect-only"], plugins=[Probe()])`. `Probe.pytest_collection_finish` calls `socket.getaddrinfo("example.invalid", 80)` and records whether it raised `OSError("network disabled in tests…")`, and the child exits non-zero if it did not. That stays out of process, which the docstring rightly requires, and it pins the guard rather than its location.
